# 用户临时自带 API Key

文档版本：0.1

## 使用方式

普通应用左侧提供“模型来源”。用户可以继续使用平台默认模型，也可以从管理员启用的可信模型目录中选择一个模型，输入自己的 API Key，并应用到当前页面。

临时 Key 只保存在 React 页面内存中。刷新、关闭标签页或清除设置后立即丢失，应用不会把它写入 localStorage、sessionStorage、草稿、场景包、完整数据、独立 HTML、共享实验库、管理员数据或模型用量记录。

## 请求边界

浏览器只把可信模型 ID 和临时 Key 发送到同源 `/api/generate`。服务端重新检查模型仍处于管理员启用状态，并使用可信目录中固定的协议、Base URL、模型名、超时和输出上限；用户不能借助自带 Key 指定任意 URL、内网地址、模型名或协议。

Key 位于 `X-Word2HTML-Temporary-API-Key` 请求头，不进入 JSON 请求体、LessonPlan、缓存键或幂等指纹。服务端只在当前请求生命周期内覆盖模型客户端配置，不保存或返回该值。部署时还应确保反向代理、APM 和错误采集系统不会记录这一请求头。

## 额度与费用

自带 Key 请求仍受匿名设备/网络来源限流、单客户端并发、全局并发、每日调用量和 token 上限保护，防止把服务端变成无限制代理。供应商费用由用户自己的 Key 承担，因此不会计入管理员页面的平台估算费用；调用与 token 仍进入总用量统计。

本功能不等于任意模型代理，也不放宽 LessonPlan Schema、能力注册、表达式白名单和浏览器安全运行时。

## 安全要求

- 公网部署必须使用 HTTPS；本地开发可以使用 `http://127.0.0.1` 或 `http://localhost`；
- 不要在共享电脑长期保持含临时 Key 的页面；使用后点击“清除临时 Key”；
- 不要在截图、录屏、问题报告或浏览器网络导出中包含 Key；
- 如果怀疑 Key 泄露，应立即到模型提供商处撤销，而不是只清除本页面；
- 管理员应在代理和日志系统中将 `X-Word2HTML-Temporary-API-Key` 配置为敏感请求头并彻底脱敏。

## 验收

启动应用后执行：

```bash
npm run acceptance:temporary-model-key -- 9333 http://127.0.0.1:5173
```

验收脚本使用假的测试字符串，不会调用模型。它检查可信目录可见、临时模式可启用、页面正文不回显 Key、浏览器存储不包含 Key，并验证刷新后临时模式自动清除。
