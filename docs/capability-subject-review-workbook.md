## 1. 使用方式

本工作簿用于把已经通过自动检查和真实浏览器验收的能力交给数学或物理审核者终审或后续复审。它不替代 `capability-verification.md` 中的晋升规则，也不允许用“AI 未发现问题”代替人工签字。当前结构化记录中的 7 项能力均已按 `word2html@0.1.0` 批准；下方空白记录栏继续作为未来版本复审或离线补录模板，不表示当前状态仍为待审核。

推荐使用可视化复核台。管理员先运行：

```bash
export WORD2HTML_ADMIN_TOKEN='使用足够长且不可猜测的随机令牌'
npm run dev
```

然后访问 `http://127.0.0.1:5173/admin/capabilities`。页面直接运行官方代表场景、展示本工作簿中的分项重点，并把审核身份、版本、结论和追加式历史保存到 `.word2html-data/capability-subject-reviews.json`。本 Markdown 保留为标准依据、离线备用表和评审沟通材料。

审核前后运行 `npm run audit:capabilities`，发布前运行 `npm run audit:capabilities:strict`。两条命令会读取同一份结构化复核记录。

在应用的官方库中打开本项列出的代表场景。每项至少检查默认值、最小值、最大值、一个中间值和一个退化或临界值，并验证播放、拖动、缩放、重置、对象样式及独立 HTML 中的结论一致性。专项浏览器命令可作为技术证据复查，但不能代替对公式、单位、适用条件和教学表述的判断。

若无法使用可视化页面，可在本文件中填写以下离线记录，并由维护者补录到页面：

| 字段 | 记录 |
| --- | --- |
| 被审版本（Git commit 或发布号） | 待填写 |
| 审核人及角色 | 待填写 |
| 审核日期 | 待填写 |
| 审阅意见 | 选填；结论为 `needs-changes` 时必填 |
| 结论 | `pending`（改为 `approved` 或 `needs-changes`） |

审核人、审核角色和被审版本始终必填；页面会把当前应用版本作为被审版本的默认推荐值。若结论为 `needs-changes`，审阅意见必须记录可复现步骤、期望结果和建议处理方式；其他结论的审阅意见选填。修复后重新执行相应自动、浏览器和学科复核。若页面记录为 `approved`，能力审计会读取该结论；维护者确认记录与被审版本一致后，再把能力注册状态从 `experimental` 晋升为 `verified` 并运行严格审计。页面不会自行修改代码或自动发布能力。

## 3. 分项复核卡

### 3.1 二维显函数 `math.function.explicit-2d`

重点检查：

- `y=A sin(Bx)` 中 `A` 对振幅、`B` 对周期 `2π/|B|` 的影响表述准确；
- `A=0`、负 `A`、接近零或负 `B` 等边界若不在当前参数范围内，应明确这是场景限制而非数学限制；
- 对含分母、根式、对数的其他显函数，定义域和间断处不能被错误连线；
- 自动量程、极值参数和采样精度不会产生错误极值或“图像不存在”的误导；
- 公式、坐标刻度、参数单位和结论一致。

### 3.2 数据表与统计图 `math.data.chart-2d`

重点检查：

- 官方月平均气温数据、城市/月份标签和摄氏度单位准确且来源可追溯；

- 表格、图例、数值标签和图中点一一对应；

### 3.5 数学参数轨迹 `math.geometry.parametric-trace-2d`

重点检查：

- 双曲线采用 `c²=a²+b²`，两支参数表达式和焦点位置正确；
- 动点到两个焦点均有直线连接与清晰距离标注；

### 3.6 二维圆盘碰撞 `physics.collision.discs-2d`

重点检查：

- 动量守恒结论只用于选定孤立系统；边界反弹存在外界冲量时不能宣称圆盘系统动量守恒；
- 恢复系数只描述法向相对速度，`e=0` 和 `e=1` 的含义准确；
- 只有理想弹性碰撞才宣称动能守恒，非弹性碰撞的能量表述准确；
- 圆盘 A、B、C 的质量、水平/竖直初速度可分别修改且不串用；擦碰、多圆盘连续接触、边界角落和不同质量/半径不会出现明显穿透或错误冲量；
- 当前不模拟摩擦、转矩、旋转、形变，应在结论适用范围中明确。

## 4. 审核完成后的维护动作

1. 将填写后的工作簿随对应版本保存，不删除问题和处理历史；
2. `needs-changes` 项保持 `subjectReview.status: 'pending'`，修复并重新验收；
3. `approved` 项在 `src/core/capabilityReadiness.ts` 记录审核摘要，必要时把注册状态晋升为 `verified`；
4. 运行 `npm test`、对应专项浏览器命令、`npm run build` 和 `npm run audit:capabilities:strict`；
5. 只有严格审计通过，才可以在 README 或发布说明中称该能力为完整验证。
