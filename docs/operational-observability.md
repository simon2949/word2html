# 结构化日志与运行告警

文档版本：0.1

实现状态：单实例首批已完成。服务端输出结构化脱敏事件，在内存中保留有限历史，并在管理员模型设置页提供只读告警视图；外部通知、跨实例汇总和长期日志平台尚未接入。

## 查看方式

- `GET /api/health` 只公开 `operations.status` 和尚未恢复的注意、错误、严重事件数量，不返回事件正文；
- 管理员登录 `/admin/models` 后可查看“脱敏告警与近期事件”；
- `GET /api/admin/operational-events` 返回同一份管理员只读快照，必须有有效管理员会话；
- 服务进程的 stdout/stderr 每行输出一个 `word2html.operational-event` JSON 对象，可由 systemd、Docker 或日志采集器直接收集。

管理员页面显示事件级别、类别、固定摘要、事件代码、最后发生时间、合并次数和恢复状态。重复事件会在五分钟窗口内合并，避免同一故障持续刷屏；恢复后的事件保留在历史中，但不再计入当前告警数量。

## 已覆盖事件

- 进程启动、停止、监听失败、未捕获异常和未处理异步拒绝；
- 存储初始化失败、就绪检查失败与恢复、SQLite active/影子状态检查失败；
- 未捕获 HTTP 500、开发渲染失败和生产静态资源读取失败；
- 模型连接测试、生成/编辑、AI 预审失败，以及平台调用、Token、费用或并发保护触发；
- 维护模式和当前存储后端等非告警运行事件。

普通输入校验、业务 400、用户个人额度或操作频率限制不会被记为系统故障。平台级模型熔断会记为注意事件。

## 脱敏边界

记录器递归屏蔽敏感字段名和常见敏感值，包括 API Key、Authorization、Cookie、CSRF Token、管理员令牌、一次性登录码、密码、临时凭据、请求正文、教学提示词和 payload。常见本机绝对路径也会替换为 `[path]`，单个字符串限制长度。

业务代码只向记录器提交固定摘要和少量枚举上下文，不提交底层异常消息、调用栈、HTTP 请求头或请求正文。管理员响应和公开健康响应均不返回原始 `Error`。

自动测试覆盖递归脱敏、结构化输出、重复合并、容量上限、恢复状态和管理员响应解析；SQLite active HTTP 验收还会检查告警接口不含敏感字段和本机路径。

## 容量与限制

默认只在当前进程内存保留最近 200 条事件，可设置：

```bash
export WORD2HTML_OPERATIONAL_EVENT_LIMIT=200
```

允许范围为 20–2000。重启服务会清空页面中的内存事件，但已经由 systemd、Docker 或其他采集器接收的 JSON 日志不受影响。

当前实现不发送邮件、短信或 Webhook，不持久化告警，也不支持多实例聚合。生产下一阶段应把 JSON 日志接入组织已有平台，在平台侧配置以下最低告警：

- 任一 `critical` 立即通知值班人员；
- `service-readiness-failed` 或 `unhandled-http-error` 持续出现时通知；
- `model-platform-limit-reached` 在课堂高峰前触发时通知管理员；
- 按 `code` 和部署实例聚合，不把完整日志重新发送给第三方模型。

发生故障时，管理员先在 `/admin/models` 查看固定摘要和事件代码，再对照部署日志中的同代码、`/api/ready` 结果和对应运维文档排查。不要为排查临时关闭脱敏或把用户提示词复制到告警平台。
