# 基于当前场景二次编辑验收

接口版本：`lesson-plan-0.9`

## 目标

用户打开导入文件、官方库、第三方库或模型生成场景后，可以输入结构修改要求并选择“修改当前”。模型获得当前紧凑 LessonPlan，上下文修改通过全部校验后替换预览；参数和纯显示设置继续由右侧面板零 token 完成。

## 验收条件

- 工作台同时提供“修改当前”和“生成新场景”，两者语义明确。
- 二次编辑请求包含当前场景反向重建的完整 `basePlan`，不依赖原始导入文件仍保存在内存中。
- 当前右侧参数值进入 `basePlan`；颜色、网格、字号等外观配置不发送给模型，并在修改结果中保留。
- 模型返回完整 LessonPlan，不执行补丁或代码。
- 编辑结果必须保持原 `templateId`、`subject` 和 `matched` 状态。
- 工具 Schema 必须固定上述三项；参数轨迹要求 `experimentSpec` 并禁止 `functionSpec`，避免标签编辑被误判为重新生成函数。
- 服务端 Schema/语义校验、浏览器表达式/数学校验、LessonScene 校验和渲染能力校验全部通过后才能提交。
- 首次结果无效时最多纠错一次；纠错仍失败时保留当前场景。
- 缓存键包含规范化修改要求、模型版本、协议版本和 `basePlan` 哈希；上下文不同不得误命中。
- 应用提交结果前生成语义变更摘要；标签、表达式、参数、测量量、矢量和约束变化可被用户核对。
- 编辑结果与基准计划语义等价时视为失败并最多纠错一次；纠错仍无变化则保留原场景。
- 缓存命中的结果也必须重新计算差异，空修改缓存不得提交。
- 0.9 应用继续接受 0.6、0.7、0.8 场景包导入。

## 代表案例

1. 导入双曲线焦点距离差场景。
2. 输入“动点到两个焦点应该通过直线连接，并标注距离”。
3. 选择“修改当前”。
4. 返回计划保持 `experiment.motion.point-2d` 和数学学科，将两条焦点连线声明为 `display: "distance"`。
5. 画布绘制无箭头直线并在中点显示 `PF1`、`PF2` 的实际长度；原有颜色和网格设置保持不变。

标签简化回归：输入“简化函数图像中的文字，如左支动点改为 Q(x,y)，PF1 x 长度单位改为 x”时，应保持参数轨迹模板，把物体标签缩短为 `Q`，并将距离矢量设为 `labelMode: "value"`；不得出现缺少 `experimentSpec` 或空 `functionSpec.formula`。
