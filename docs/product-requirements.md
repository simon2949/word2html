# Word2HTML 交互教学内容生成器：MVP 产品需求

文档版本：0.3

状态：持续实施

## 1. 产品定义

Word2HTML 是一个统一的网页工作台。用户输入一段 K12 数学、物理、化学或地理教学描述，系统将它转换成可修改参数、可调整显示效果、可直接操作并可导出为 HTML 的交互场景。

产品不区分教师端和学生端，也不引入班级、课程、作业或成绩角色。所有用户使用同一个编辑与预览界面；公开服务阶段只增加用于费用、安全和管理边界的游客、普通用户与管理员身份。

产品的核心不是让 AI 每次编写一份新的 HTML，而是：

1. 理解用户意图；
2. 匹配已有教学模板；
3. 生成或修改结构化场景；
4. 由固定渲染器显示交互内容；
5. 将固定运行时与场景数据一起导出为 HTML。

## 2. MVP 目标

- 用户可以用自然语言创建一个椭圆焦点距离和演示。
- 用户可以通过右侧控件修改长轴、短轴和显示效果，这类修改不调用模型。
- 所有参数修改在本地即时生效，不需要再次调用模型。
- 相同或相似诉求优先复用已有模板和场景。
- 用户可以保存、恢复并导出可独立运行的交互 HTML。
- 系统能够阻止非法参数和不安全的生成内容。

## 3. MVP 非目标

- 教师、学生等教学角色划分，以及班级或机构多级权限；
- 班级、课程、作业和成绩管理；
- 多人实时协作；
- 覆盖全部 K12 知识点；
- 允许模型生成并执行任意 JavaScript；
- 完整的模板市场或公开内容社区；
- 学习行为分析和学习效果评估。

这些非目标只限定当前 MVP。产品的后续目标包括：即使用户请求没有命中任何现有教学模板，也能通过通用渲染器和安全场景协议生成可立即预览的函数图像或实验演示，而不是只能返回“不支持”。

当前实施路线聚焦对象级编辑、统一可视化原语、能力注册表、复用优先生成、样式/布局预设和生成反馈。已有保存、导出和审核修改版本继续维护，但本轮不新增版本管理、分享链接、派生协作、课堂模式、PWA 或移动端专项工程。详细阶段和完成门槛见 `implementation-roadmap.md`。

“现有能力收口”已经完成：统一审计能够区分平台注册状态、技术证据成熟度和学科人工复核，当前 9 项能力均具备官方代表场景、专项浏览器断言和当前版本学科批准记录。新增物理、化学或地理原语继续执行 `capability-verification.md` 中的相同门槛。

## 4. 核心使用场景

### 4.1 首次生成

用户输入：

> 绘制一个椭圆，椭圆上的点可以拖动，显示它到两个焦点的距离，并演示距离之和不变。长轴和短轴可以调整。

系统应识别椭圆模板，抽取默认或显式参数，生成结构化场景并打开可交互预览。

### 4.2 使用面板修改

用户修改长轴、短轴、颜色、网格、标签、辅助线或动画速度。预览应立即更新，不触发 AI 请求。

### 4.3 判断生成路径

用户输入教学内容后，系统先判断处理路径：已有审核模板直接复用，不调用大模型；参数或显示修改引导用户使用右侧设置面板；没有匹配模板的新教学内容才调用大模型。系统必须在调用前向用户展示判断结果。

### 4.4 保存与导出

用户保存场景后可以再次打开；导出的 HTML 在不连接生成服务的情况下仍可运行参数调整、拖动、播放和重置功能。

## 5. 页面结构

桌面端采用一个统一工作台：

- 顶部工具栏：场景名称、保存状态、撤销、重做、导入、导出；
- 左侧输入区：教学内容描述、生成路径判断和生成结果；
- 中间预览区：公式说明、交互画布、缩放、适应窗口、播放、暂停、重置和全屏；
- 右侧设置区：参数、显示效果、对象三个标签页；选择画布对象后自动打开对象属性；
- 底部状态区：模板来源、校验结果、复用方式和本次 token 使用情况。

窄屏下，输入区和设置区改为可展开抽屉，交互画布保持主区域。

## 6. 功能需求

### FR-01 自然语言创建

- 接受中文自然语言输入；
- 识别学科、知识点、目标、对象、参数、交互和显示要求；
- 优先匹配已审核模板；
- 参数或显示修改不进入大模型生成流程，并引导用户使用右侧设置；
- 未命中模板的新内容才允许调用已配置的大模型服务；
- 调用前显示所选路径和原因；
- 生成期间显示明确状态；
- 无法支持时说明缺少的组件，不能返回不可运行页面。

### FR-02 模板复用

- 精确匹配时直接复用已有场景；
- 命中同类模板时只创建参数实例；
- 相似场景只生成差异补丁；
- 全新场景才进入完整生成流程；
- 界面显示本次属于“直接复用、模板复用、相似修改或全新生成”。

### FR-03 参数编辑

- 每个参数具有名称、含义、单位、默认值、范围和步长；
- 同时支持滑块和数值输入；
- 参数约束在提交前和运行时各校验一次；
- 参数变化立即刷新图形和派生值；
- 提供恢复默认值功能。

### FR-04 显示效果编辑

MVP 支持：

- 坐标轴和网格开关；
- 点、线、标签、辅助线和数值开关；
- 主图形、辅助线和重点对象颜色；
- 点大小，以及实心、带轮廓、带投影三种点样式；
- 主图线和辅助线可分别设置线宽，并选择实线、虚线或点划线；
- 标签字号；
- 动画速度；
- 轨迹显示；
- 画布缩放、全屏和重置。

显示效果通过允许列表配置，不接受任意 CSS。样式修改应直接作用于当前场景，不调用大模型；完整场景文件和独立 HTML 导出需保留这些设置。旧场景缺少新增样式字段时使用模板默认值，不阻止导入。

“显示效果”负责整个场景的统一默认值，包括预设、整体显示内容、各类对象的默认颜色以及点线默认样式；“对象”负责选中具体对象后的局部细调。对象局部覆盖优先于整体默认值，修改整体显示不得静默删除已有局部覆盖。界面必须明确展示对象当前是“继承整体设置”还是“已有局部设置”，并提供清除局部设置、重新继承整体效果的操作。

对象级显示编辑支持：

- 点击画布中的点、线、曲线、标签、矢量、约束或实验物体，也可从对象列表中选择；
- 画布和对象列表同步高亮当前对象，选择状态只属于工作台运行时，不写入场景文件；
- 点仅开放颜色、大小、点样式和显示状态，线仅开放颜色、线宽、线型和显示状态，标签仅开放颜色、字号和显示状态；
- 局部对象设置优先于同角色和场景级默认值，可单独恢复当前对象默认样式；
- 不存在、不可编辑或字段类型不匹配的对象覆盖必须在渲染前拒绝；
- 对象修改进入现有撤销、重做和自动草稿流程，全程不调用模型。

显示面板提供受控预设：

- 样式预设包括教学简洁、重点突出、投影高对比、深色演示和打印友好；
- 布局预设包括图像居中、图像加测量值、图像加参数区和紧凑控制；
- 用户先选择卡片预览，明确点击应用后才产生场景修改；
- 样式预设只写入白名单外观字段，不保存 CSS、选择器或脚本；
- 默认保留对象局部样式，只有用户勾选“同时清除对象局部样式”才删除对象覆盖；
- 预设应用、恢复模板外观、撤销、重做、草稿和独立 HTML 全程不调用模型；
- 缺少 `layoutPreset` 的旧场景按“图像加参数区”处理。

### FR-05 场景交互

- 支持鼠标和触摸拖动；
- 支持播放、暂停和重置；
- 被约束的点不能离开目标曲线；
- 拖动和参数变化期间实时更新测量值；
- 场景错误不能导致整个工作台崩溃。
- 支持缩小、放大和一键适应窗口；
- 函数图像或实验展示画布占满其圆角容器，测量值和操作栏不得挤占画布框；
- 参数变化后自动恢复到完整显示场景的适应状态；
- 坐标系 x、y 方向采用同一像素比例，网格保持正方形；
- 坐标轴根据当前缩放自动选择刻度间隔，并避免标签过密。

### FR-06 生成请求路由

- 生成前必须查询本地权威能力注册表，并展示识别学科、知识点、命中来源、所需/缺失能力、预计参数、交互方式和模型调用原因；
- 已知缺少渲染原语的请求在模型调用前停止，保留当前场景并给出具体缺口和替代建议，不用 Schema 错误代替能力说明；
- 创建场景依次查询精确缓存、官方库和已审核第三方库；精确及同能力候选直接本地复用，相似候选只作为同学科、同运行时的收窄二次编辑基准；
- 本地未审核第三方条目不得参与自动复用；复用判断不得为检索额外调用模型；
- 能力指纹忽略参数当前值但绑定模板、学科、对象、交互和参数结构；创建缓存绑定能力 ID，二次编辑缓存绑定完整基准 LessonPlan，禁止跨能力或跨基准命中；
- 已知运行时的首次模型请求必须携带能力 ID，服务端将 subject、templateId 和 functionSpec/experimentSpec 工具 Schema 收窄到该能力，浏览器对返回规划再次执行能力一致性检查；
- 命中模板时直接产生参数实例，记录零模型 token；
- 设置类请求不生成场景，也不调用模型；
- 新内容只有在生成端点已配置时才发起模型调用；
- 用户可明确选择“修改当前”，应用把当前已校验 LessonScene 反向压缩为 LessonPlan，并连同修改要求发送给模型；导入场景、官方库、第三方库以及本地参数修改后的场景均适用；
- 二次编辑只允许在当前 `templateId` 和学科内修改安全表达式、对象、测量量、矢量、约束及教学说明；切换教学内容必须使用“生成新场景”；
- 二次编辑工具 Schema 按当前模板收窄：参数轨迹不能漂移成通用函数，通用函数也不能返回实验规格；
- 运动点标签使用短名称并由画布自动追加坐标；矢量标注支持完整“标签/数值/单位”和仅数值两种模式；
- 二次编辑完成后保留当前颜色、网格、缩放偏好等本地显示配置，并建立 `parentSceneId` 血缘；
- 二次编辑提交前对基准计划和结果计划执行语义差异比较；状态区列出标签、表达式、参数、测量量、矢量和约束等实际变化；
- 模型未产生语义变化时不得显示成功，允许把无变化错误反馈给模型纠错一次；缓存中的空修改不得复用；
- 模型只输出模板选择、参数补丁、安全通用函数规格或受限时间实验规格；规划经 LessonPlan 校验并由本地模板/运行时实例化后，还必须经过完整 LessonScene 校验才能替换当前场景；
- 模型不可用、输出无效或渲染器不支持时保留当前场景；
- 首次规划未通过服务端或浏览器本地校验时，将精确错误反馈给模型并最多纠错一次；本地确定性修复成功时不触发纠错调用；
- 单次生成流程最多调用模型两次，第二次仍失败立即停止，避免不可控 token 消耗；
- 相同当前 LessonPlan 与相同修改要求使用上下文缓存，命中后不调用模型；
- 记录生成路径、原因和模型 token 使用情况。

### FR-07 保存与历史

- MVP 默认保存在浏览器本地；
- 自动保存草稿；
- 支持撤销和重做；
- 支持另存为副本；
- 保存场景协议版本、模板版本和渲染器版本。
- 草稿保存对象级外观覆盖，但不保存当前选中的对象。

### FR-08 导入与导出

- 导出完整 LessonScene 结构化场景文件，保留当前结构、参数、场景外观与对象级外观覆盖；
- 将当前已校验场景反向压缩为 `.word2html.json` LessonPlan 包，保留二次编辑后的声明式结构和当前参数值，用于分享、第三方库复用及后续二次编辑；
- 导入 LessonScene 场景文件或紧凑 `.word2html.json` LessonPlan 包，并完成版本、协议、表达式、学科不变量和渲染能力检查；
- 紧凑场景包不保存颜色、字号等纯显示外观，重新导入时复用审核运行时的默认外观；
- 导出可独立运行的 HTML，并按工作台相同的优先级还原对象级外观覆盖；
- 导出页面不包含模型密钥；
- 导出页面不需要调用 AI 才能完成已有交互。

### FR-09 官方库与第三方库

- 官方库随应用版本发布，只包含经过代码审查、学科审查和回归测试的实验；
- 成功导入的外部场景自动保存到本地第三方库并标记为“本地未审核”，本地记录不能自声明为已审核；
- 文件能够运行只表示协议兼容，不等同于教学内容正确；外部文件不能通过自声明获得“官方”或“已审核”状态；
- 相同能力指纹的第三方文件复用同一条目，避免重复占用存储；
- 用户可以从两个库直接打开场景，并继续修改参数、显示效果和导出 HTML；
- 本地第三方条目允许移除，不影响当前已打开场景；
- 只有用户点击“提交共享审核”并确认后才上传紧凑场景包，导入行为本身不触发网络提交；
- 服务端重新校验当前协议与表达式白名单，按 SHA-256 去重，并将新内容隔离为 `pending`；
- 每个新的内容哈希按照版本化审核标准自动执行一次 AI 预审；未发现问题时记录 `no-issues`，发现问题时保存位置、严重程度、原因和处理建议；
- AI 预审不能修改目录审核状态；模型失败或输出无效时保存失败原因，条目继续保持 `pending`，由管理员人工审核或触发重试；
- 公共共享目录只返回 `verified` 条目，浏览器仍须重新实例化并执行完整 LessonScene 校验；
- 管理员通过 `/admin/reviews` 可视化审核台或 Bearer API 读取队列，并维护 `pending`、`needs-changes`、`verified`、`rejected` 和 `deprecated` 状态；
- 服务端为提交、版本关联、AI预审排队/完成/失败及每次人工状态变化追加管理员可见的审核事件，不向公共库或提交者状态接口公开内部历史；
- 提交者可以用本地精确场景包查询自己的版本状态；退回意见应在第三方库中醒目展示，并支持打开修改、预填审核要求、保存本地修改版本和重新提交；
- 当前单机文件存储属于共享目录 MVP；生产阶段改为身份认证、数据库、不可变审核日志和多实例并发控制。

### FR-10 错误处理

- 对非法参数给出具体原因和可接受范围；
- 对不支持的自然语言请求保留原场景；
- 模型请求失败时允许重试，不清空用户输入；
- 场景版本不兼容时停止导入并给出迁移提示。

### FR-11 无模板动态场景（分阶段实现）

当前完成：通用二维显式函数绘图器；一条参数方程、极坐标或隐函数零等值线的关系曲线运行时；表格、分组柱状图、折线图和散点图运行时；包含中点、平移、旋转、轴对称、位似、垂足、圆/直线/线段约束和本地轨迹采样的二维几何运行时；最多 4 个数学参数点或物理质点的时间实验；以及 2–8 个圆盘的确定性接触运行时。月平均气温折线图、旋转圆周轨迹、极坐标玫瑰线、隐函数圆、三角形边角面积、双曲线焦点距离差、单摆、弹簧振子和二维多圆盘碰撞作为验收案例。后续阶段：带摩擦或转矩的刚体、光学和电路原语。

- 未命中现有模板时，模型先尝试组合已审核的通用渲染器和交互原语；
- 函数类内容优先使用通用函数绘图器，模型只提供安全表达式、参数、定义域、标注和交互配置；
- 实验类内容使用声明式对象、状态变量、约束、时间推进规则和可验证不变量组成 SceneDraft；
- SceneDraft 不包含 HTML、CSS、JavaScript、URL、网络请求或浏览器 API；
- 动态草案必须通过协议、安全表达式、对象引用、资源上限、学科数值和渲染能力校验后才能进入预览；
- 通过校验但尚未人工审核的内容明确标记为“实验性场景”；
- 缺少必要渲染原语时，系统说明具体缺口并保留当前场景，不伪造无法正确运行的演示；
- 用户确认或保存后的动态场景按规范化教学目标和能力指纹缓存，相同诉求优先复用；
- 高频且稳定的实验性场景可以提升为审核模板，后续生成不再调用模型；
- 最终用户体验应做到：没有命中预制模板时，仍可在一次生成流程内获得安全、可操作的函数或实验演示。

后续能力严格按 `implementation-roadmap.md` 推进：

1. [已完成] 对象选择、对象属性面板和对象级外观覆盖；
2. [已完成] 样式预设与布局预设；
3. [已完成] 本地权威能力注册表和可理解的生成反馈；
4. [已完成] 精确复用、相似修改、原语组合和能力缺口反馈；
5. [首批实现完成，正在收口证据] 数学与物理原语扩展；
6. [实施中：模型适配首批已完成] 统一模型适配、混合 API Key、防滥用、轻量登录和生产部署基础；
7. [待开始] 化学与地理原语扩展。

版本分享派生和课堂专项增强不进入本轮排期；已有相关能力只做兼容、安全和回归维护。

### 6.1 公开服务与模型配置

- 部署以公共托管服务为主，同时继续支持通过环境变量自行部署；
- 服务端首批统一支持 Anthropic 兼容与 OpenAI 兼容协议，MiniMax 保持默认兼容配置；
- 管理员负责启用可信提供商、Base URL、模型和平台额度，普通用户只能从启用项中选择；
- 平台 API Key 不返回前端；用户可以临时提供自己的 Key，但第一版只保存在页面会话内存中；
- 普通用户不能提交任意 Base URL，服务端必须拒绝非 HTTPS、带凭据、内网、回环和其他未授权目标；
- 生成模型和 AI 预审模型可以分别配置，公共状态接口只返回提供商、协议、模型、地址和是否已配置；
- 无论使用哪种模型，输出都必须进入相同 LessonPlan、能力、表达式和固定运行时校验，不能直接生成可执行代码。

### 6.2 访问与费用边界

- 游客可以浏览官方库和已审核第三方库，进行本地编辑、导入、导出，并使用自己的临时 API Key；
- 使用平台付费 API、提交共享审核和后续跨设备数据时要求登录；
- 身份只分游客、普通用户、管理员，不增加教师/学生界面分叉；
- 登录优先使用邮箱验证码、魔法链接或 OAuth，不自行保存密码；
- 模型生成、二次编辑、自动纠错、预审和共享提交分别限流，并具有并发、输入、token、每日费用和幂等限制；
- 账号、匿名设备和网络来源共同参与风险判断，避免学校共享出口只因 IP 被整体误伤；
- 只保存运行服务所需的最少身份与用量信息，不收集非必要的未成年人真实资料。

## 7. 非功能需求

### 正确性

- 公式和派生值由确定性运行时计算；
- 场景包含可执行的不变量检查；
- 生成结果通过协议、依赖关系和学科规则校验后才能渲染。

### 性能

- 参数和显示选项的本地修改应让用户感觉即时；
- 拖动动画在常见电脑和平板上保持流畅；
- 大型学科组件按需加载，不进入所有场景的首屏包。

### 安全

- 不执行模型返回的任意脚本；
- 表达式只允许使用白名单函数和运算符；
- 富文本经过净化；
- 导出文件不泄露服务端配置、密钥或内部提示词。

### 可访问性

- 所有设置控件具有可读标签；
- 颜色不是表达状态的唯一手段；
- 关键操作支持键盘；
- 动画可以暂停，并尊重减少动态效果的系统设置。

## 8. 数据与成本指标

系统至少记录以下匿名技术指标：

- 模板命中级别；
- 输入、输出和缓存 token；
- 生成耗时与失败原因；
- 用户生成后修改了哪些配置类型；
- 场景是否成功保存或导出；
- 每个成功保存场景的平均 token 成本。

建议重点关注：模板复用率、首次生成可用率、平均修改次数、导出成功率和单个有效场景成本。

## 9. MVP 完成标准

- 椭圆案例满足 `ellipse-mvp-acceptance.md` 中全部必需项；
- 连续调整参数不会产生模型请求；
- 相同椭圆请求可以命中模板；
- 保存后重新打开能恢复参数和显示效果；
- 导出的 HTML 可以离线完成全部既有交互；
- 场景中不存在任意脚本执行入口。
