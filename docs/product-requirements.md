# Word2HTML 交互教学内容生成器：MVP 产品需求

文档版本：0.1  
状态：开发前草案

## 1. 产品定义

Word2HTML 是一个统一的网页工作台。用户输入一段 K12 数学、物理、化学或地理教学描述，系统将它转换成可修改参数、可调整显示效果、可直接操作并可导出为 HTML 的交互场景。

产品不区分教师端和学生端，也不在 MVP 中引入班级、课程、作业或角色权限。所有用户使用同一个编辑与预览界面。

产品的核心不是让 AI 每次编写一份新的 HTML，而是：

1. 理解用户意图；
2. 匹配已有教学模板；
3. 生成或修改结构化场景；
4. 由固定渲染器显示交互内容；
5. 将固定运行时与场景数据一起导出为 HTML。

## 2. MVP 目标

- 用户可以用自然语言创建一个椭圆焦点距离和演示。
- 用户可以通过控件或自然语言修改长轴、短轴和显示效果。
- 所有参数修改在本地即时生效，不需要再次调用模型。
- 相同或相似诉求优先复用已有模板和场景。
- 用户可以保存、恢复并导出可独立运行的交互 HTML。
- 系统能够阻止非法参数和不安全的生成内容。

## 3. MVP 非目标

- 教师、学生、管理员等角色划分；
- 班级、课程、作业和成绩管理；
- 多人实时协作；
- 覆盖全部 K12 知识点；
- 允许模型生成并执行任意 JavaScript；
- 完整的模板市场或公开内容社区；
- 学习行为分析和学习效果评估。

这些非目标只限定当前 MVP。产品的后续目标包括：即使用户请求没有命中任何现有教学模板，也能通过通用渲染器和安全场景协议生成可立即预览的函数图像或实验演示，而不是只能返回“不支持”。

## 4. 核心使用场景

### 4.1 首次生成

用户输入：

> 绘制一个椭圆，椭圆上的点可以拖动，显示它到两个焦点的距离，并演示距离之和不变。长轴和短轴可以调整。

系统应识别椭圆模板，抽取默认或显式参数，生成结构化场景并打开可交互预览。

### 4.2 使用面板修改

用户修改长轴、短轴、颜色、网格、标签、辅助线或动画速度。预览应立即更新，不触发 AI 请求。

### 4.3 判断生成路径

用户输入教学内容后，系统先判断处理路径：已有审核模板直接复用，不调用大模型；参数或显示修改引导用户使用右侧设置面板；没有匹配模板的新教学内容才调用大模型。系统必须在调用前向用户展示判断结果。

### 4.4 保存与导出

用户保存场景后可以再次打开；导出的 HTML 在不连接生成服务的情况下仍可运行参数调整、拖动、播放和重置功能。

## 5. 页面结构

桌面端采用一个统一工作台：

- 顶部工具栏：场景名称、保存状态、撤销、重做、导入、导出；
- 左侧输入区：教学内容描述、生成路径判断和生成结果；
- 中间预览区：公式说明、交互画布、缩放、适应窗口、播放、暂停、重置和全屏；
- 右侧设置区：参数、显示效果、说明文字三个标签页；
- 底部状态区：模板来源、校验结果、复用方式和本次 token 使用情况。

窄屏下，输入区和设置区改为可展开抽屉，交互画布保持主区域。

## 6. 功能需求

### FR-01 自然语言创建

- 接受中文自然语言输入；
- 识别学科、知识点、目标、对象、参数、交互和显示要求；
- 优先匹配已审核模板；
- 参数或显示修改不进入大模型生成流程，并引导用户使用右侧设置；
- 未命中模板的新内容才允许调用已配置的大模型服务；
- 调用前显示所选路径和原因；
- 生成期间显示明确状态；
- 无法支持时说明缺少的组件，不能返回不可运行页面。

### FR-02 模板复用

- 精确匹配时直接复用已有场景；
- 命中同类模板时只创建参数实例；
- 相似场景只生成差异补丁；
- 全新场景才进入完整生成流程；
- 界面显示本次属于“直接复用、模板复用、相似修改或全新生成”。

### FR-03 参数编辑

- 每个参数具有名称、含义、单位、默认值、范围和步长；
- 同时支持滑块和数值输入；
- 参数约束在提交前和运行时各校验一次；
- 参数变化立即刷新图形和派生值；
- 提供恢复默认值功能。

### FR-04 显示效果编辑

MVP 支持：

- 坐标轴和网格开关；
- 点、线、标签、辅助线和数值开关；
- 主图形、辅助线和重点对象颜色；
- 线宽、点大小和字号；
- 动画速度；
- 轨迹显示；
- 画布缩放、全屏和重置。

显示效果通过允许列表配置，不接受任意 CSS。

### FR-05 场景交互

- 支持鼠标和触摸拖动；
- 支持播放、暂停和重置；
- 被约束的点不能离开目标曲线；
- 拖动和参数变化期间实时更新测量值；
- 场景错误不能导致整个工作台崩溃。
- 支持缩小、放大和一键适应窗口；
- 函数图像或实验展示画布占满其圆角容器，测量值和操作栏不得挤占画布框；
- 参数变化后自动恢复到完整显示场景的适应状态；
- 坐标系 x、y 方向采用同一像素比例，网格保持正方形；
- 坐标轴根据当前缩放自动选择刻度间隔，并避免标签过密。

### FR-06 生成请求路由

- 命中模板时直接产生参数实例，记录零模型 token；
- 设置类请求不生成场景，也不调用模型；
- 新内容只有在生成端点已配置时才发起模型调用；
- 模型只输出模板选择、参数补丁、安全通用函数规格或受限时间实验规格；规划经 LessonPlan 校验并由本地模板/运行时实例化后，还必须经过完整 LessonScene 校验才能替换当前场景；
- 模型不可用、输出无效或渲染器不支持时保留当前场景；
- 记录生成路径、原因和模型 token 使用情况。

### FR-07 保存与历史

- MVP 默认保存在浏览器本地；
- 自动保存草稿；
- 支持撤销和重做；
- 支持另存为副本；
- 保存场景协议版本、模板版本和渲染器版本。

### FR-08 导入与导出

- 导出结构化场景文件；
- 导入场景文件并完成版本及合法性检查；
- 导出可独立运行的 HTML；
- 导出页面不包含模型密钥；
- 导出页面不需要调用 AI 才能完成已有交互。

### FR-09 错误处理

- 对非法参数给出具体原因和可接受范围；
- 对不支持的自然语言请求保留原场景；
- 模型请求失败时允许重试，不清空用户输入；
- 场景版本不兼容时停止导入并给出迁移提示。

### FR-10 无模板动态场景（分阶段实现）

当前完成：通用二维显式函数绘图器，以及通用二维点运动的时间轴、状态推进、轨迹、测量、速度/加速度矢量、播放、导出和缓存闭环。后续阶段：多物体和约束原语。

- 未命中现有模板时，模型先尝试组合已审核的通用渲染器和交互原语；
- 函数类内容优先使用通用函数绘图器，模型只提供安全表达式、参数、定义域、标注和交互配置；
- 实验类内容使用声明式对象、状态变量、约束、时间推进规则和可验证不变量组成 SceneDraft；
- SceneDraft 不包含 HTML、CSS、JavaScript、URL、网络请求或浏览器 API；
- 动态草案必须通过协议、安全表达式、对象引用、资源上限、学科数值和渲染能力校验后才能进入预览；
- 通过校验但尚未人工审核的内容明确标记为“实验性场景”；
- 缺少必要渲染原语时，系统说明具体缺口并保留当前场景，不伪造无法正确运行的演示；
- 用户确认或保存后的动态场景按规范化教学目标和能力指纹缓存，相同诉求优先复用；
- 高频且稳定的实验性场景可以提升为审核模板，后续生成不再调用模型；
- 最终用户体验应做到：没有命中预制模板时，仍可在一次生成流程内获得安全、可操作的函数或实验演示。

建议的能力实现顺序：

1. 通用二维函数绘图器；
2. 通用时间轴、数值状态和轨迹运行时；
3. 力学矢量原语（已完成），继续扩展多物体与约束原语；
4. 化学容器、物质、浓度和反应进度原语；
5. 地理地图、图层、时间序列和空间标注原语；
6. SceneDraft 自动验证、实验性预览、缓存和模板晋升流程。

## 7. 非功能需求

### 正确性

- 公式和派生值由确定性运行时计算；
- 场景包含可执行的不变量检查；
- 生成结果通过协议、依赖关系和学科规则校验后才能渲染。

### 性能

- 参数和显示选项的本地修改应让用户感觉即时；
- 拖动动画在常见电脑和平板上保持流畅；
- 大型学科组件按需加载，不进入所有场景的首屏包。

### 安全

- 不执行模型返回的任意脚本；
- 表达式只允许使用白名单函数和运算符；
- 富文本经过净化；
- 导出文件不泄露服务端配置、密钥或内部提示词。

### 可访问性

- 所有设置控件具有可读标签；
- 颜色不是表达状态的唯一手段；
- 关键操作支持键盘；
- 动画可以暂停，并尊重减少动态效果的系统设置。

## 8. 数据与成本指标

系统至少记录以下匿名技术指标：

- 模板命中级别；
- 输入、输出和缓存 token；
- 生成耗时与失败原因；
- 用户生成后修改了哪些配置类型；
- 场景是否成功保存或导出；
- 每个成功保存场景的平均 token 成本。

建议重点关注：模板复用率、首次生成可用率、平均修改次数、导出成功率和单个有效场景成本。

## 9. MVP 完成标准

- 椭圆案例满足 `ellipse-mvp-acceptance.md` 中全部必需项；
- 连续调整参数不会产生模型请求；
- 相同椭圆请求可以命中模板；
- 保存后重新打开能恢复参数和显示效果；
- 导出的 HTML 可以离线完成全部既有交互；
- 场景中不存在任意脚本执行入口。
