# 能力验收与晋升规则

版本：0.1  
更新日期：2026-08-31

## 1. 目的

本文件用于回答三个不同问题，三者不能混为一个状态：

1. **平台注册状态**：能力注册表中的 `experimental` 或 `verified`，用于路由和产品展示；
2. **技术证据成熟度**：注册、官方代表场景、自动检查、真实浏览器和独立 HTML 是否形成闭环；
3. **学科人工复核**：公式、定义、单位、适用条件和教学表述是否由合适的审核者确认。

AI、Schema 和自动测试可以帮助发现问题，但不能代替学科人工复核。缺少专项浏览器记录也不会自动篡改已有平台注册状态，而是作为待补证据单独显示。

实现入口：`src/core/capabilityReadiness.ts`。

## 3. 自动审计

日常检查：

```bash
npm run audit:capabilities
```

它检查：

- 每项注册能力是否恰有一份验收证据记录；
- 注册模板是否接入运行时和独立 HTML 导出器；
- 是否存在直接对应的官方代表场景；
- 官方场景能否通过当前确定性结构、表达式和预演检查；
- 专项真实浏览器证据及学科复核是否完成；
- 所引用的验收文档是否真实存在。

普通审计只在注册、绑定或文档等完整性损坏时返回失败，适合开发过程和 CI。发布门禁使用：

```bash
npm run audit:capabilities:strict
```

只要仍有 `technical-ready`、`evidence-incomplete` 或 `blocked`，严格模式就返回非零。当前基线应通过严格模式；后续非零结果视为新增能力尚未收口或现有证据发生回退。

## 4. 学科人工复核清单

审核者应打开官方代表场景，并至少检查默认值、最小值、最大值、一个中间值及一个退化或临界值。

7 项人工复核能力的官方场景、专项命令和分项边界已整理在 `capability-subject-review-workbook.md`。全部能力当前均有 `word2html@0.1.0` 的批准记录；早期 `1.0`、`2.0` 记录继续保留在追加式历史中，没有被覆盖。后续复审推荐在 `/admin/capabilities` 可视化复核台完成；结构化记录由 `npm run audit:capabilities` 读取，Markdown 工作簿保留为标准依据和离线备用模板。

### 4.1 教学目标与范围

- 学科、知识点、年级范围和演示目标一致；
- 标题、公式、说明和图像表达同一概念；
- 明确近似条件、定义域、适用前提和不成立的情况；
- 不把数值演示、相关性或特殊案例写成普遍证明或因果结论。

### 4.2 学科正确性

- 公式、符号、正负方向、坐标系和角度约定正确；
- 参数、读数及派生量的单位一致，量纲合理；
- 几何不变量、物理守恒条件或数据来源能由场景实际支持；
- 参数边界、分支、间断、碰撞、约束和退化状态不会产生误导结果。

### 4.3 视觉与交互

- 图形完整占据展示框，适应窗口、缩放和重置有效；
- x、y 等比例时网格保持正方形，刻度与标签不明显重叠；
- 点、线、焦点、距离、矢量、轨迹和单位可辨认，文字没有错误截断；
- 拖动、播放、暂停、参数编辑、对象细调和预设不破坏学科结论；
- 窄屏、深色、打印友好预设及独立 HTML 中仍可理解和操作。

### 4.4 安全与可维护性

- 场景只含协议允许的声明式数据，不含 HTML、脚本、URL 或外部依赖；
- 资源数量、采样、速度和数值范围符合注册限制；
- 完整数据、紧凑场景包、草稿、撤销重做和独立 HTML 的语义一致；
- 标题、数据、图片和教学文字不存在明显版权、隐私或不适合 K12 的问题。

### 4.5 审核记录

每项能力的人工结论至少记录：

- 能力 ID、代表场景 ID 和被审版本；
- 审核人、审核角色和日期；
- 审阅意见；结论为 `needs-changes` 时必填，其他结论选填；
- `approved` 或 `needs-changes` 结论。

审核人、审核角色和被审版本始终必填，被审版本默认推荐当前应用版本。“AI 未发现问题”不是 `approved`。只有完成上述记录，结构化学科复核状态才可改为 `approved`。

## 5. 晋升为 verified 的门槛

一项新能力只有同时满足以下条件，才允许从 `experimental` 晋升为 `verified`：

1. 能力注册、类型、Schema、验证器、固定渲染器和独立 HTML 导出完整；
2. 至少有一个直接对应的官方代表场景；
3. 官方场景通过确定性自动检查和相关单元/属性测试；
4. 有带断言、可重复执行的专项真实浏览器脚本，并记录通过；
5. 工作台、窄屏和独立 HTML 的关键交互一致；
6. 学科人工复核为 `approved`，且审核记录完整；
7. 能力边界、验收文档、README 和注册表同步；
8. `npm run audit:capabilities:strict` 不再因该能力失败。

若能力后续修改公式语义、协议字段、数值算法或关键交互，必须重新运行对应自动与浏览器验收；若改变教学结论或适用条件，还必须重新进行学科人工复核。
