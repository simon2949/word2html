# Word2HTML 实现路线

路线版本：0.5

更新日期：2026-08-31

状态：已确认，R6 公开使用基础能力开始实施

## 1. 路线目标

下一阶段不以增加更多相互独立的特殊案例为主，而是把 Word2HTML 建设成由安全、可组合、可审核的教学可视化原语构成的统一工作台。

本路线聚焦六条主线：

1. 点击画布对象并进行对象级编辑；
2. 建立统一的可视化原语层；
3. 建立本地权威的能力注册表；
4. 按“精确复用 → 相似修改 → 原语组合”的顺序生成场景；
5. 提供不调用模型的样式预设和布局预设；
6. 在生成前后提供可理解、可操作的路径与能力反馈。

## 2. 当前不扩展的范围

本轮路线暂不安排以下新增能力：

- 新的场景版本管理、分享链接、派生或多人协作流程；
- 新的课堂模式、PWA 离线、移动端专项适配、打印课件或无障碍专项工程。

已有的本地草稿、撤销重做、场景包、完整数据、HTML 导出、审核修改版本和基础响应式/无障碍行为继续维护，不在本轮删除或重构。安全修复、协议兼容和回归问题不受上述范围限制。

## 3. 目标架构

```text
用户描述或当前场景修改
  → 确定性意图路由
  → 能力注册表 + 官方库/已审核第三方库检索
  → 精确复用 / 相似场景补丁 / 已审核原语组合
  → 紧凑 LessonPlan
  → Schema、表达式、引用、学科规则和能力校验
  → LessonScene 场景图
  → 固定渲染器、对象属性面板和预设系统
  → 交互预览与独立 HTML
```

模型继续只生成紧凑声明式数据，不生成或执行 HTML、CSS、JavaScript、URL 和第三方依赖。参数、纯外观、对象样式和预设切换全部在浏览器本地完成，模型调用为 0。

## 4. 实施阶段

### R1 对象选择与属性面板

状态：已完成首批闭环（2026-08-23），验收记录见 `object-editing-acceptance.md`。

目标：用户可以点击画布中的点、线、曲线、标签、矢量、约束或实验物体，只修改当前对象。

实现内容：

- 建立 `SceneObject.id` 与 SVG/Canvas 渲染对象之间的稳定映射；
- 增加运行时 `selectedObjectId`，选中对象在画布和对象列表中同步高亮；
- 右侧增加“对象属性”区域，只显示该对象允许修改的属性；
- 为点、主图线、辅助线、标签、矢量、约束和轨迹定义有限的可编辑字段；
- 设计可选的对象外观覆盖，解析优先级为“对象覆盖 → 角色默认 → 场景默认 → 模板默认”；
- 对象覆盖只允许颜色、大小、线型、线宽、标签显示等白名单字段，不接受任意 CSS；
- 支持撤销、重做、恢复对象默认值、完整数据导入导出和独立 HTML；
- 紧凑场景包继续不保存纯外观覆盖，以保持文件紧凑并减少模型上下文。

首批覆盖椭圆、二次函数、通用函数和时间实验。选择状态属于运行时状态，不写入模板，也不改变数学或物理计算。

完成门槛：

- 点击对象后属性面板展示正确对象和允许字段；
- 只改变被选对象，不误改同类对象；
- 对象样式修改不调用模型；
- 无效或不存在的对象 ID 被拒绝；
- 画布、撤销重做、草稿恢复和独立 HTML 浏览器验收通过。

浏览器验收脚本：`npm run acceptance:object-editor -- 9333 http://127.0.0.1:5181`。

### R2 样式与布局预设

状态：已完成（2026-08-26），包括自动测试与真实浏览器验收，记录见 `preset-acceptance.md`。

目标：用户可以一键获得适合不同演示目的的统一效果，再继续局部调整。

实现内容：

- 首批样式预设：教学简洁、重点突出、投影高对比、深色演示和打印友好；
- 首批布局预设：图像居中、图像加测量值、图像加参数区和紧凑控制；
- 预设由受控令牌和现有外观字段组成，不包含 CSS 文本；
- 应用预设生成一个本地外观补丁，支持撤销和恢复模板默认值；
- 对象级覆盖保留在预设之上，除非用户明确选择“同时重置对象样式”；
- 预设预览、应用和撤销均不调用模型。

完成门槛：每个预设在四类现有运行时、窄画布和独立 HTML 中无明显遮挡，且 Schema、视觉快照和浏览器交互验收通过。

浏览器验收脚本：`npm run acceptance:presets -- 9333 http://127.0.0.1:5173`。

### R3 能力注册表与生成反馈

状态：实现与自动测试已完成（2026-08-24）。能力清单和扩展规则见 `capability-registry.md`。

目标：在调用模型前就知道系统能否真正渲染用户诉求，并把判断过程说清楚。

每项能力至少声明：

- 稳定能力 ID、学科、知识点和支持的意图词；
- 所需原语、参数类型、交互、测量量和不变量；
- 对应模板或运行时、验证器和导出器；
- 数量、表达式、持续时间和资源限制；
- `built-in`、`experimental` 或 `verified` 状态；
- 不支持时的缺口说明和可行替代方案。

路由返回统一的结构化判断结果：识别出的学科和知识点、命中来源、所需能力、缺失能力、预计可调参数、交互方式、是否调用模型以及原因。

完成门槛：

- 模板、通用函数和时间实验不再使用分散的条件判断描述能力；
- 已支持请求能定位到具体模板或运行时；
- 不支持请求能指出缺少的原语，而不是暴露 Schema 错误；
- 参数和显示请求稳定路由到右侧设置，模型调用为 0；
- 注册表、运行时、验证器和导出器之间的一致性自动测试通过。

### R4 复用优先的生成与局部修改

状态：实现与自动测试已完成（2026-08-24）。执行顺序、指纹和缓存隔离规则见 `reuse-first-generation.md`。

目标：尽量在已有内容上修改，减少重复生成、token 消耗和不可控差异。

固定处理顺序：

1. 当前请求是否只是参数、外观或对象属性修改；
2. 官方模板或已审核场景精确匹配；
3. 相同能力指纹、不同参数的模板实例；
4. 相同知识点与交互模式的相似场景；
5. 使用已注册原语组合新场景；
6. 缺少原语时停止并返回具体缺口。

实现内容：

- 统一规范化描述、能力指纹和缓存键；
- 检索默认先使用本地确定性元数据，不为检索额外调用模型；
- 相似修改只发送当前紧凑 LessonPlan、修改要求和相关能力 Schema；
- 优先返回受约束结构补丁；必须返回完整计划的运行时继续使用当前收窄 Schema；
- 只向模型提供当前学科、运行时和原语需要的字段；
- 校验成功且确有变化的结果才进入缓存；
- 高频、稳定、审核通过的组合可晋升为官方模板。

完成门槛：相同请求、参数/显示修改和缓存命中为 0 token；相似请求能够说明复用了什么、修改了什么；缓存不得跨能力或跨基准场景误命中。

### R5 数学与物理原语扩展

状态：数学第一批基础二维几何、第二批关系曲线、第三批几何约束/轨迹/变换、第四批数据图表，以及物理第一批二维圆盘接触均已完成实现、自动测试、专项浏览器验收和当前版本学科人工复核。验收范围分别见 `geometry-primitives-acceptance.md`、`relation-curve-2d-acceptance.md`、`geometry-transform-acceptance.md`、`data-chart-2d-acceptance.md` 与 `collision-2d-acceptance.md`；当前注册能力均已晋升为 `verified`。

目标：先用统一契约扩大现有强项，不再为每个实验增加独立页面代码。

数学优先顺序：

1. [已完成] 点、线段、射线、向量、圆弧、多边形和测量标注；
2. [已完成首批] 参数方程、隐函数和极坐标曲线；
3. [已完成首批] 几何约束、轨迹和变换；
4. [已完成首批] 数据表、柱状图、折线图和散点图。

物理优先顺序：

1. [已完成首批] 矩形接触面、圆盘碰撞检测和二维法向碰撞；
2. 刚体、铰链和滑轮；
3. 波、光线、反射、折射和透镜；
4. 电路元件、连线、开关和仪表。

每个原语必须同时提供类型与 Schema、能力注册、验证器、固定渲染器、对象属性声明、独立 HTML 导出、审核检查、官方示例和自动测试，缺一项不得标记为 `verified`。

数学第一批使用 `math.geometry.primitives-2d` / `geometrySpec` 作为紧凑协议。参数、点坐标表达式、对象引用和测量均为声明式数据；可拖动点必须直接绑定两个坐标参数。

数学第二批使用 `math.curve.relation-2d` / `relationSpec`。模型只声明参数方程 `x(t), y(t)`、极坐标 `r(theta)` 或隐函数零等值线 `F(x,y)=0` 中的一种，以及参数、范围和教学文字；本地运行时固定采样参数曲线并以固定网格提取隐函数等值线。场景包不得携带采样点、SVG 路径、帧或执行代码。该数值显示适合 K12 探索，但不是符号求解器，也不承诺像素级精确交点。

数学第三批继续扩展 `geometrySpec`，支持中点、平移、旋转、轴对称、位似、垂足，以及圆/直线/线段上的受约束拖点。轨迹只声明目标点和驱动参数，本地固定采样 241 点；构造依赖图必须无环，模型和场景包不得携带采样点或绘制路径。`lesson-plan-1.3` 保持旧几何规格兼容，并新增官方旋转圆周轨迹示例。

数学第四批使用 `math.data.chart-2d` / `dataChartSpec`。`table`、`bar`、`line` 共用类别数组和等长数值系列；`scatter` 只使用数值点。模型不得生成 SVG、绘图库选项或绘制代码。固定运行时负责表格语义结构、坐标轴、正方形网格、自动量程、图例、数值标签、缩放和系列级样式。`lesson-plan-1.4` 新增该规格并继续兼容导入 0.6–1.3 场景包。

物理第一批使用 `physics.collision.discs-2d` / `collisionSpec`。模型只声明 2–8 个圆盘的初始位置、速度、半径、质量、矩形边界、重力和恢复系数；本地固定 240 Hz 求解器负责接触检测、穿透修正、边界反弹和法向冲量。模型不能手写碰撞时刻、逐帧轨迹或代码。预演会拒绝初始重叠、越界、过大预计速度、非有限状态和未解算穿透。

以上已交付能力均已通过当前 `verified` 门槛，但注册限制不因此放宽：数据图表仍不提供饼图、堆叠图、自动分箱、统计拟合或动态数据源；二维关系曲线仍只支持一条关系曲线，不提供符号求交、动画等值线或多曲线独立样式；二维碰撞仍不模拟摩擦、转矩、方向、圆盘形变或任意刚体。新增原语仍须独立通过真实浏览器、窄屏、独立 HTML 和课堂学科复核后才能标记为 `verified`。

### R6 公开使用基础能力

状态：方案已确认。部署以公共托管服务为主，同时保持自行部署能力；模型费用采用平台有限额度与用户临时自带 API Key 的混合模式；普通编辑不强制登录，平台付费模型和共享提交使用轻量身份边界。

目标：在继续增加学科原语之前，先让当前能力能够安全、可控地服务更多用户，同时保持本地编辑、模板复用和导出流程低门槛。

### R7 化学与地理原语扩展

目标：在 R3–R6 的统一注册、验证、编辑、导出和公开服务基础稳定后扩展新学科。

化学优先顺序：容器和器材 → 物质与状态 → 浓度/体积/温度 → 滴加、加热、沉淀和气泡 → 反应进度与微观粒子。

地理优先顺序：地图和区域 → 经纬线、比例尺和空间标注 → 图层与时间序列 → 地形剖面和等高线 → 地球运动、太阳光线、气压、风向和洋流。

首批原语仍执行与数学、物理相同的安全、能力、导出和审核门槛；模型不能借新学科名义返回任意绘图代码。

## 5. 跨阶段约束

- 新能力必须先进入注册表，再允许路由或模型使用；
- 新字段优先设计为可选字段，并为旧 LessonScene 提供确定性默认值；
- 同一份能力声明尽量生成或驱动模型 Schema、校验错误、设置面板和审核检查，避免多处重复维护；
- 每个模型调用都记录路由原因、复用来源、输入/缓存/输出 token 和纠错次数；
- 用户没有要求结构变化时，不把外观或参数操作发送给模型；
- 能力不足时保留当前场景，显示缺失能力和处理建议，不伪造成功；
- 独立 HTML 必须与工作台使用相同的字段语义和默认值。

## 6. 每阶段交付清单

每个阶段只有在以下内容同时完成后才能进入下一阶段：

1. 产品需求和协议文档；
2. 类型、Schema 和兼容策略；
3. 固定运行时与设置界面；
4. 导入、导出和独立 HTML；
5. 单元、属性、组件和浏览器验收；
6. 官方示例或测试场景；
7. 管理员自动检查与人工审核要点；
8. token 与复用路径验证。

## 7. 路线效果指标

重点观察以下工程和产品指标：

- 参数、显示、对象属性和预设修改的零模型调用率；
- 官方模板、已审核场景和相似场景的复用率；
- 首次生成通过完整本地校验的比例；
- 不支持请求中能够给出具体能力缺口的比例；
- 每个成功可用场景的平均输入、缓存输入和输出 token；
- 独立 HTML 与工作台渲染一致性；
- 每项注册能力具备完整验证器、导出器和浏览器验收的覆盖率。
