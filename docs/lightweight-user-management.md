# 轻量用户与管理员账号管理

文档版本：0.1

实现状态：R6.4 首批单实例方案已完成。

## 为什么采用一次性登录码

当前目标是用尽量少的账号复杂度区分游客、普通用户和管理员，而不是建设教师、学生、班级、课程或成绩系统。首批由管理员创建账号并通过可信渠道发出一次性登录码，因此不需要保存密码，也不依赖邮件服务或 OAuth 平台。

这适合小规模试用、校内试点和受控邀请。若以后开放公众自助注册，应改接邮箱验证码、魔法链接或 OAuth，并补充验证码、账号恢复、邮件发送限流和隐私合规流程。

## 三类身份的边界

| 身份 | 无需登录可用 | 需要登录后可用 |
| --- | --- | --- |
| `guest` | 浏览实验库、本地编辑、参数和样式调整、导入导出、使用当前页面临时自带 API Key | 无平台付费模型额度，不能提交共享审核 |
| `user` | 包含游客全部能力 | 使用管理员分配的平台模型额度、提交共享审核 |
| `admin` | 独立管理员会话 | 模型设置、第三方库审核、能力复核、用户创建/暂停/额度管理 |

普通用户仍共用同一个应用界面，不区分教师端和学生端。

## 管理员操作

1. 启动服务前，从操作系统环境注入 `WORD2HTML_ADMIN_TOKEN`。
2. 访问 `http://127.0.0.1:5173/admin/users`，输入管理员令牌。
3. 填写用户显示名称、每日模型调用次数和每日 Token，点击“创建并签发登录码”。
4. 复制页面中只显示一次的 `w2h-login-…` 登录码，通过可信渠道交给用户。
5. 在用户卡片中查看当日调用，按需调整额度、暂停/恢复账号或重新签发登录码。

重新签发会覆盖此前尚未使用的登录码。暂停账号后，已有签名会话在下一次服务端请求时也会被拒绝；恢复账号不会自动恢复已经清除的浏览器 Cookie，需要用户使用新码登录。

## 普通用户操作

1. 打开普通应用，点击右上角“登录”。
2. 粘贴管理员提供的一次性登录码并提交。
3. 登录成功后页面显示用户名称和每日平台额度；刷新页面仍保持登录。
4. 用户可在账号窗口退出。登录码使用后立即失效，不能再次登录；换设备或会话丢失时由管理员重新签发。

## 数据与安全边界

- 用户目录默认保存在 `.word2html-data/users.json`，使用临时文件加原子替换写入，文件权限为 `0600`；
- 目录只保存登录码的 SHA-256 摘要，不保存登录码原文和用户密码；
- 登录码原文只在创建或重新签发的管理员响应中出现一次，前端关闭提示后不再读取；
- 用户会话保存在签名的 `HttpOnly`、`SameSite=Strict` Cookie 中，前端脚本和浏览器存储无法读取；
- 退出登录使用 CSRF Token；生产 HTTPS 部署必须设置 `WORD2HTML_SECURE_COOKIES=true`；
- 服务端每次受保护请求都会读取用户目录，因此暂停账号不需要等待 Cookie 到期；
- 用户记录仅包含随机账号 ID、管理员填写的显示名称、状态、额度和必要时间，不要求真实姓名、学校或班级；
- 模型用量键由服务端对账号 ID 做不可逆摘要，不把内部计量键发给浏览器。

生产环境应单独注入高熵 `WORD2HTML_USER_SESSION_SECRET`。若未设置，当前实现会从模型用量摘要密钥派生，便于本地启动，但不应作为正式密钥管理方案。所有密钥都不要使用 `VITE_` 前缀，也不要提交到仓库。

## 配置

```bash
export WORD2HTML_ADMIN_TOKEN='高熵管理员令牌'
export WORD2HTML_USER_SESSION_SECRET='独立的高熵会话签名密钥'
export WORD2HTML_SECURE_COOKIES=true
npm run start
```

非敏感配置：

- `WORD2HTML_USER_DIRECTORY_FILE`：用户目录路径，默认 `.word2html-data/users.json`；
- `WORD2HTML_USER_DAILY_CALLS`：新账号默认每日调用次数，默认 `20`；
- `WORD2HTML_USER_DAILY_TOKENS`：新账号默认每日 Token，默认 `100000`。

## 当前限制与下一阶段

- 账号目录是单机 JSON，适合单实例 MVP，不适合多个 Node 进程同时写入；
- 模型用量仍是进程内存计数，服务重启后当日计数清零；
- 签名会话不是服务端可枚举会话，当前通过账号暂停完成统一撤销；
- 暂未实现自助注册、邮箱投递、忘记登录、单设备退出、账号删除或复杂组织权限；
- 共享提交尚未在管理员记录中展示提交账号，后续应加入账号级提交历史与处置审计；
- R6.5 应把用户目录和业务数据迁移到 SQLite/PostgreSQL，把用量、限流、幂等和短任务状态迁移到 Redis，并补充备份恢复、日志脱敏和部署监控。

## 验证

先保持应用服务运行，再执行：

```bash
WORD2HTML_ADMIN_TOKEN='与服务端相同的管理员令牌' \
  npm run acceptance:user-session -- 9333 http://127.0.0.1:5173/admin/users
```

脚本会在隔离浏览器中创建临时用户、登录、检查一次性登录码不能复用、确认 Cookie 对页面脚本不可见、刷新恢复会话，并由管理员暂停账号验证即时失效。脚本不调用大模型，不产生模型 token。
