# 能力注册表与生成判断

版本：0.1  
更新日期：2026-08-31

## 1. 目的

能力注册表是应用关于“当前版本真正能生成、校验、渲染和导出什么”的本地权威来源。自然语言路由先查询注册表，再决定复用模板、调用模型生成受约束规划，或因为缺少运行时原语而停止。

大模型不能临时生成脚本、HTML 或渲染器来绕过注册表。这样可以避免模型返回格式正确但应用无法展示的内容，也避免为明确不支持的请求消耗 token。

实现入口：`src/core/capabilityRegistry.ts`。

## 3. 生成判断结构

路由统一返回以下信息：

- `subject`、`topic`：识别出的学科和知识点；
- `matchSource`：已审核模板、已注册运行时、右侧本地设置、能力缺口或待模型识别；
- `requiredCapabilities`、`missingCapabilities`：所需能力及具体缺失原语；
- `expectedParameters`、`interactions`：预计可调参数和交互方式；
- `willCallModel`、`modelCallReason`：是否调用模型及原因。

左侧“生成能力判断”在用户提交前直接展示这些信息。已知缺口点击生成时会保留当前场景，并把缺口及建议写入结果卡。

## 4. 新增能力的规则

新增模板或运行时不能只增加意图词。一个能力条目至少要同时具备：

1. 稳定能力 ID、学科、知识点、意图词和匹配优先级；
2. 所需原语、参数类型、交互、测量值、不变量和资源限制；
3. 可用的模板 ID、固定渲染器、LessonScene 验证器和独立 HTML 导出器；
4. 不支持边界和替代方案；
5. 注册表一致性、路由、渲染、校验和导出自动测试。

只有经过学科审核、交互验收和回归测试的模板或受限通用运行时标记为 `verified`。已接入但证据或能力边界尚未收口的运行时标记为 `experimental`。

## 5. 自动检查

`src/core/capabilityRegistry.test.ts` 检查：

- 能力和缺口 ID 唯一；
- 每项能力声明完整绑定；
- 注册模板与实际独立 HTML 导出器一致；
- 典型模板、通用函数、二维关系曲线、数据图表、二维几何、二维圆盘碰撞和时间实验可定位到具体运行时；
- 化学、电路和任意刚体等已知缺口在模型调用前返回具体原语。

`src/components/GenerationCapabilityDetails.test.ts` 检查用户能够看到学科、知识点、命中来源、模型决策及处理建议。

`npm run audit:capabilities` 进一步把注册绑定、官方代表场景、自动运行检查、真实浏览器证据和学科人工复核汇总成同一份就绪度报告。日常审计只在完整性损坏时失败；发布门禁使用 `npm run audit:capabilities:strict`。当前 9 项能力均已通过严格审计；状态定义、晋升门槛和后续复审规则见 `capability-verification.md`，分项学科检查标准见 `capability-subject-review-workbook.md`。
