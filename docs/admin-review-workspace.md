# 管理员可视化审核台

## 进入页面

管理员令牌只从启动服务的操作系统环境读取，不写入 `.env.example`、前端变量或仓库：

```bash
export WORD2HTML_ADMIN_TOKEN='使用足够长且不可猜测的随机令牌'
npm run dev
```

浏览器访问：

```text
# 第三方库提交审核
http://127.0.0.1:5173/admin/reviews

# 平台能力学科复核
http://127.0.0.1:5173/admin/capabilities
```

在登录框输入与 `WORD2HTML_ADMIN_TOKEN` 相同的值。登录成功后，服务端签发最长 8 小时的 HttpOnly、SameSite=Strict 会话 Cookie；原始令牌不会进入 URL、`localStorage` 或 `sessionStorage`。生产环境通过 HTTPS 提供服务时设置：

```bash
export WORD2HTML_SECURE_COOKIES=true
```

## 页面结构

### 第三方库审核 `/admin/reviews`

- 左侧是审核队列，可按人工状态、AI 风险、预审失败和学科筛选，也可搜索名称、文件名或条目编号。
- 中间直接运行提交的场景，使用与普通应用相同的渲染器。管理员可拖动、播放、缩放、切换宽屏/窄屏、修改参数和显示效果；这些测试不会改写提交文件。
- 右侧先显示 AI 预审摘要，再提供“场景自动检查”和人工终审。自动检查覆盖当前协议、参数边界矩阵、运行区间采样、控件覆盖及视口缩放。
- AI 预审区的“放大阅读”会在独立大字号弹窗中展示完整问题；弹窗支持 A−/A+ 在 90%–160% 之间调节字号。
- 自动检查在浏览器中使用正式安全运行时完成，不调用大模型、不消耗 token；检查结果也可以放大阅读。
- 人工终审区要求确认科学内容、参数边界、视觉效果和主要交互。自动检查已经运行且没有失败项、四项人工检查全部完成后，才允许审核通过。自动提醒项允许管理员复核后通过，自动失败项会阻止发布。
- 如果提交是退回后的修改版，预览区上方会显示原退回意见、参数/表达式/标签等确定性差异和“查看原版本”；原版本也会显示“转到修改版审核”。
- “审核时间线”按时间倒序显示提交、版本关联、AI 排队/完成/失败，以及每次人工状态变化和审核意见；关联版本可直接跳转。

### 能力学科复核 `/admin/capabilities`

- 左侧列出 7 项已完成技术验收、仍待学科终审的能力，并显示 `待复核`、`需要修改` 或 `已批准`；
- 中间直接运行该能力的官方代表场景；有多个代表场景时可以在预览上方切换；
- 右侧显示该能力专属的四项学科复核重点，并提供审核人、审核角色、被审版本和审阅意见；
- 审核人、审核角色和被审版本在保存草稿、标记需要修改或审核通过时均为必填；被审版本默认推荐当前应用版本，也可以改为 Git commit 或发布号；
- `审核通过` 还要求全部检查项已勾选；`标记需要修改` 必须填写审阅意见，其他结果的审阅意见选填；
- 每次保存草稿、退回或批准都会追加带时间的审核快照，不覆盖旧记录；
- 此流程只保存人的判断，不调用 MiniMax，也不会因为 AI 结论自动批准能力。

能力复核记录默认写入 `.word2html-data/capability-subject-reviews.json`。可通过操作系统环境变量 `WORD2HTML_CAPABILITY_REVIEWS_FILE` 或启动参数 `--capability-review-file` 指向持久卷。`npm run audit:capabilities` 会读取同一文件，因此管理员页面和命令行审计使用同一结论。

能力复核记录格式当前为 `0.2`。现有 `0.1` 文件会兼容读取，旧的“问题与处理结果”自动映射为“审阅意见”；管理员下一次保存任一记录时，整个文件会原子升级到 `0.2`，并停止写入已删除的“已覆盖的参数和边界”和“接受的限制”。

## 状态操作

- `审核通过并发布`：设置为 `verified`，立即进入公共共享第三方库。
- `退回修改`：设置为 `needs-changes`，必须填写具体问题和修改建议，不会公开。
- `拒绝收录`：设置为 `rejected`，必须填写原因，需要二次确认，不会公开。
- `从公开库下架`：把已经通过的内容设置为 `deprecated`。
- `重新预审`：按当前版本审核标准重新调用 MiniMax；无论模型结果如何，都不会自动发布。
- `运行检查`：对提交的原始场景执行确定性检查，不会保存管理员在预览中临时调整的参数，也不会调用 MiniMax。

## 自动检查内容

- 协议与当前参数：检查 LessonScene Schema、安全表达式、对象引用、当前参数和模板语义。
- 参数边界矩阵：测试全部默认值、每个可编辑数值参数的最小值/最大值，以及全部最小值和全部最大值组合。椭圆长短轴使用合法联动值测试单项边界。
- 运行区间采样：椭圆验证焦点距离和，二次函数验证顶点与对称性，通用函数采样定义域，时间实验采样整个时段及绳长约束。
- 可编辑参数控件：提示声明为可编辑但没有界面控件的参数。
- 视口与缩放：检查坐标范围及缩放能力；实际文字重叠和窄屏效果仍由管理员目测。

自动结果是即时报告，切换条目或刷新页面后需要重新运行，避免旧结果被误用于新版本。

## 审核时间线

新提交会从 `submitted` 和首次 `pre-review-queued` 开始记录。后续 AI 预审完成、失败、管理员重试、退回、通过、拒绝、下架以及修改版本关联都会追加事件，不再覆盖此前的操作说明。历史事件只由管理员列表接口返回，不进入公共共享库，也不进入提交者的精确状态查询结果。

旧的 Lesson Directory 0.1 文件不需要手工迁移：读取旧条目时，服务端会根据 `createdAt`、当前 `preReview` 和最近一次 `reviewedAt` 生成兼容时间线；该条目下一次发生写操作时再把兼容历史与新事件一并持久化。

现有 Bearer 管理接口仍可用于自动化脚本。网页登录的写操作还会校验 CSRF token；会话失效后页面会要求重新登录。

## 当前边界

当前仍是单实例、单管理员令牌 MVP。第三方目录事件只能标记为“管理员”；能力复核表要求审核者自行填写姓名和角色，但尚未与独立账号身份绑定。JSON 文件也不具备防篡改签名。多管理员身份、强制实名映射、数据库不可变审计、提交者通知和多实例并发控制仍属于生产化阶段。
